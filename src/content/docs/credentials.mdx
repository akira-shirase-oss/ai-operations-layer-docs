`GET /v1/admin/credentials` is the whole credential surface in one read: projects, ingest keys and API
tokens — ids, names, actors, scopes, project lists, created/expiry/revocation times. Metadata only:
**hashes and secrets are never served.** An allowed read is not audited; a denial always is.

```sh run=control
curl -s http://127.0.0.1:57400/v1/admin/credentials -H "Authorization: Bearer $AIOPS_ADMIN_TOKEN" \
  | python3 -c 'import sys,json
d=json.load(sys.stdin)
print("projects:", ", ".join(p["slug"] for p in d["projects"]))
print("ingest keys:", ", ".join(k["name"] for k in d["ingest_keys"]))
print("tokens:", ", ".join(t["actor"] + "(" + "+".join(t["scopes"]) + ")" for t in d["tokens"]))'
```

```text output=control
projects: docs
ingest keys: suite
tokens: docs(read), docs-ops(read+operate), ops(admin)
```

## Revoking by id

Both revoke routes are `POST` under `/v1/admin/credentials/…` and need `admin`. A revoke writes its
audit row *before* answering — allowed or denied — and the store's denial of an unknown id is a `404`
that is itself audited:

```sh run=control
KID=$(curl -s http://127.0.0.1:57400/v1/admin/credentials -H "Authorization: Bearer $AIOPS_ADMIN_TOKEN" \
  | python3 -c 'import sys,json; print(json.load(sys.stdin)["ingest_keys"][0]["id"])')
curl -s -X POST "http://127.0.0.1:57400/v1/admin/credentials/ingest-keys/$KID/revoke" -H "Authorization: Bearer $AIOPS_ADMIN_TOKEN"; echo
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:57400/v1/ingest \
  -H "Authorization: Bearer $AIOPS_INGEST_KEY" -H "Content-Type: application/json" -d '{}'
```

```text output=control
{"id":"<uuid>","revoked":true}
401
```

## Why the revoked key dies on its next presentation

The collector caches credential lookups (valid and invalid apart, evicted oldest-first) so hot ingest
never waits on the store. A revoke route therefore does two things beyond the database write: it
**evicts the credential's cached answer in the same process**, and it commits the audit row before
replying. The key's next `POST /v1/ingest` is `401` — it doesn't wait out the cache TTL.

> The `admin` CLI revoke path (`admin revoke-ingest-key`, a store-only call) still relies on the
> resolver's normal TTL — worst case the cache lifetime. The HTTP revoke is the incident tool: it
> kills the cached answer now. Mint the replacement first, then revoke — a revoked name is not
> reusable.

Tokens revoke the same way: `POST /v1/admin/credentials/tokens/{id}/revoke`. The id for either kind
comes from `GET /v1/admin/credentials` — credential ids are the public handles; the secrets behind
them are never on the wire.
