`aiops-sdk` is the crate your host service emits through. Everything on this page runs on your machine
against a local collector (`AIOPS_ENDPOINT` points at it; the suite resets to a fresh `docs` project first).

{/* snippet sdk: snippets/restart.sh */}

Its guarantees are the point:

- **Never blocks the request path beyond its bound.** Emitting is a non-blocking enqueue into a
  bounded queue; a full queue **drops and counts**.
- **Never panics.** Calls return values or mark the client failed; the SDK — and your service — keep
  working when the collector is down.
- **Every drop is counted** and every counter is exposable to the host; `stats` ride on every batch
  so the latest cumulative values survive lost batches.
- **Context propagation** follows OTel-compatible formats; event payloads conform to the versioned
  [ingest contract](/ingest-contract/) — no schema drift without a version bump.
- **Server-side only.** An ingest key in a browser is a published key.

## Add it and emit an operation

```toml not-run="a Cargo.toml fragment, not a command"
[dependencies]
aiops-sdk = { path = "../ai-operations-layer/crates/aiops-sdk" }
tokio = { version = "1", features = ["full"] }
```

The SDK takes its endpoint and ingest key explicitly (the environment is the usual source):

```sh run=sdk
export AIOPS_ENDPOINT=http://127.0.0.1:57400
```

```rust not-run="a Rust excerpt; the runnable version is crates/aiops-sdk/examples/first_operation.rs"
use aiops_sdk::{Client, Config, Finish, StepKind, UncertainReason};

let client = Client::start(&Config::new(endpoint, key, "checkout"))?;
let op = client.operation("checkout.answer").request_id("req-42").start();

// A model step that failed before it left the host, retried, then succeeded.
let generate = op.step(StepKind::Model, "draft-reply").model("acme-small-4").start();
let retry = generate
    .finish(Finish::failed(aiops_sdk::FailureClass::Transport, "connect_refused"))
    .retry()
    .start();
retry.finish(Finish::succeeded().usage(132, 480).cost_estimate(2_052, "USD", "list-price"));

// A publish whose reply never came: the effect may have happened.
let publish = op.step(StepKind::Tool, "publish").external_effect(true).start();
publish.finish(Finish::uncertain(UncertainReason::TimeoutAfterSend, "publish_timeout"));

op.finish(Finish::uncertain(UncertainReason::TimeoutAfterSend, "publish_timeout"));
let stats = client.shutdown(std::time::Duration::from_secs(2)).await;
```

Outcomes are **declared**: `Finish::succeeded()`, `Finish::failed(class, code)`,
`Finish::uncertain(reason, code)`. A `finish().retry().start()` is how a retried attempt is written —
the timeline shows both attempts, the failed one counted.

## Run the real example

The product ships `crates/aiops-sdk/examples/first_operation.rs` — the same shape as above, end to
end. Run it against your local collector:

```sh run=sdk
cargo run --release -p aiops-sdk --example first_operation
```

```text output=sdk
emitted 8 events: 8 accepted, 0 dropped (every drop is counted)
```

The operation appears in the console under request ID `example-1` — one operation, a retried model
step, an `external_effect` publish whose finish is `uncertain` (flagged: the effect may have
happened), and an `uncertain` operation finish.

## What happens with the collector down

The same example finishes anyway: events sit in the bounded queue, flush when the collector recovers,
and `stats.dropped()` counts what the deadline or a full queue lost — the next successful batch's
`stats` reports it, so the loss is visible in the console rather than silent.

## Marking effects and uncertainty

A step that may change the outside world — charge a card, send an email, merge a PR — should be
declared with `.external_effect(true)`, and a request that left the host without a usable answer
finishes `uncertain` with one of the three reasons. The timeline then flags it: *the effect may have
happened* — check the authoritative store, don't blindly retry.
